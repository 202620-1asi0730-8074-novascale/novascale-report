
# Capítulo III: Requirements Specification

## 3.1. User Stories

| Epic / Story ID | Título | Descripción | Criterios de Aceptación | Relacionado con (Epic ID) |
| :--- | :--- | :--- | :--- | :--- |
| **EPIC-01** | Autenticación y permisos | Gestionar el acceso de los usuarios a NovaLeads, incluyendo el inicio de sesión, los roles y los permisos que determinan las funcionalidades disponibles para cada usuario. | **Given** que un usuario tiene credenciales y permisos registrados, **When** solicita acceder a NovaLeads, **Then** el sistema valida sus credenciales y le permite acceder únicamente a las funcionalidades autorizadas. | — |
| **HU-01** | Inicio de sesión | Como usuario, quiero iniciar sesión para acceder a las funcionalidades de NovaLeads según mis permisos. | **Given** que el usuario tiene credenciales válidas, **When** solicita iniciar sesión, **Then** el sistema autentica al usuario y le concede acceso según sus permisos. **Given** que las credenciales del usuario no son válidas, **When** solicita iniciar sesión, **Then** el sistema rechaza la autenticación. | **EPIC-01** |
| **HU-02** | Gestión de usuarios y permisos | Como dueño, quiero gestionar los permisos de los usuarios para controlar qué funcionalidades puede utilizar cada vendedor. | **Given** que el usuario tiene permisos de dueño y existe un vendedor registrado, **When** modifica los permisos del vendedor, **Then** el sistema guarda los nuevos permisos y los aplica al vendedor. **Given** que el usuario no tiene permisos de dueño, **When** intenta modificar los permisos de un vendedor, **Then** el sistema rechaza la operación. | **EPIC-01** |
| **EPIC-02** | Dashboard y métricas | Proporcionar indicadores y gráficos que permitan a los dueños visualizar el rendimiento general del negocio y a los vendedores consultar sus propios resultados de ventas. | **Given** que existen datos registrados y el usuario tiene permisos para consultar métricas, **When** solicita las métricas del negocio, **Then** el sistema proporciona los indicadores correspondientes a su rol y permisos. | — |
| **HU-03** | Dashboard del dueño | Como dueño, quiero visualizar un dashboard con indicadores y gráficos para conocer el estado general de las ventas y los leads de mi negocio. | **Given** que el usuario tiene permisos de dueño y existen leads y ventas registrados, **When** solicita los indicadores del negocio, **Then** el sistema proporciona los indicadores correspondientes al estado de los leads y al rendimiento de las ventas. | **EPIC-02** |
| **HU-04** | Dashboard del vendedor | Como vendedor, quiero visualizar mis indicadores de ventas para conocer mi rendimiento personal. | **Given** que el usuario es vendedor y tiene ventas registradas, **When** solicita sus indicadores de ventas, **Then** el sistema proporciona únicamente los indicadores correspondientes a sus ventas. | **EPIC-02** |
| **HU-05** | Visualización de ventas por vendedor | Como dueño, quiero visualizar las ventas realizadas por cada vendedor para evaluar el rendimiento individual del equipo. | **Given** que el usuario tiene permisos de dueño y existen ventas asociadas a diferentes vendedores, **When** solicita las ventas por vendedor, **Then** el sistema proporciona las ventas correspondientes a cada vendedor. | **EPIC-02** |
| **EPIC-03** | Gestión de leads | Permitir registrar, consultar, filtrar, clasificar y actualizar leads, así como utilizar etiquetas para identificar intereses relacionados con productos y facilitar su seguimiento comercial. | **Given** que existen leads registrados y el usuario tiene permisos para gestionarlos, **When** solicita una operación sobre los leads, **Then** el sistema permite realizar únicamente las operaciones autorizadas. | — |
| **HU-06** | Registro de leads | Como vendedor, quiero registrar nuevos leads para incorporarlos al proceso comercial. | **Given** que el usuario tiene permisos para crear leads y proporciona la información requerida, **When** solicita registrar un lead, **Then** el sistema crea el lead y conserva la información proporcionada. **Given** que falta información requerida, **When** el usuario solicita registrar un lead, **Then** el sistema rechaza el registro. | **EPIC-03** |
| **HU-07** | Filtrado de leads | Como usuario, quiero filtrar los leads para encontrar rápidamente aquellos que cumplen determinados criterios. | **Given** que existen leads registrados, **When** el usuario solicita los leads utilizando criterios como estado, vendedor o etiqueta, **Then** el sistema proporciona únicamente los leads que cumplen los criterios seleccionados. | **EPIC-03** |
| **HU-08** | Cambio de estado de un lead | Como usuario, quiero cambiar el estado de un lead para mantener actualizado su progreso dentro del proceso comercial. | **Given** que existe un lead y el usuario tiene permisos para modificarlo, **When** asigna un estado válido al lead, **Then** el sistema actualiza el estado del lead. **Given** que el estado proporcionado no es válido, **When** el usuario solicita modificar el estado, **Then** el sistema rechaza la modificación. | **EPIC-03** |
| **HU-09** | Etiquetado de leads por producto | Como usuario, quiero asignar etiquetas relacionadas con productos a los leads para identificar sus intereses comerciales. | **Given** que existe un lead y existen etiquetas de productos registradas, **When** el usuario asigna una o más etiquetas al lead, **Then** el sistema asocia las etiquetas seleccionadas al lead. | **EPIC-03** |
| **HU-10** | Gestión de etiquetas | Como usuario autorizado, quiero crear y editar etiquetas para mantener organizada la información comercial. | **Given** que el usuario tiene permisos para gestionar etiquetas, **When** crea una etiqueta con información válida, **Then** el sistema registra la nueva etiqueta. **Given** que existe una etiqueta y el usuario tiene permisos para modificarla, **When** actualiza su información, **Then** el sistema guarda los cambios y actualiza las asociaciones correspondientes. | **EPIC-03** |
| **EPIC-04** | Gestión de contactos | Centralizar la información de los contactos y permitir identificar si corresponden a leads o clientes, además de consultar y actualizar sus datos según los permisos del usuario. | **Given** que existen contactos registrados y el usuario tiene permisos de acceso, **When** solicita información de contactos, **Then** el sistema proporciona la información que corresponde a sus permisos. | — |
| **HU-11** | Visualización de contactos | Como usuario, quiero visualizar una lista de contactos para consultar las personas registradas en el sistema. | **Given** que existen contactos registrados y el usuario tiene permisos de acceso, **When** solicita los contactos, **Then** el sistema proporciona los contactos disponibles según sus permisos. | **EPIC-04** |
| **HU-12** | Clasificación de contacto | Como usuario, quiero identificar si un contacto es un lead o un cliente para conocer su situación comercial. | **Given** que existe un contacto registrado y tiene una clasificación válida, **When** el usuario consulta la información del contacto, **Then** el sistema proporciona su clasificación como lead o cliente. | **EPIC-04** |
| **HU-13** | Edición de información de contacto | Como usuario autorizado, quiero editar la información de un contacto para mantener sus datos actualizados. | **Given** que existe un contacto y el usuario tiene permisos de edición, **When** modifica los datos con información válida, **Then** el sistema actualiza la información del contacto. **Given** que el usuario no tiene permisos de edición, **When** solicita modificar un contacto, **Then** el sistema rechaza la operación. | **EPIC-04** |
| **EPIC-05** | Gestión de conversaciones | Gestionar las conversaciones vinculadas con WhatsApp, incluyendo la creación automática de contactos, notificaciones, temporizadores, prioridades y filtros para organizar las conversaciones. | **Given** que existen conversaciones asociadas a contactos, **When** un usuario autorizado solicita gestionarlas, **Then** el sistema permite realizar las operaciones correspondientes a sus permisos. | — |
| **HU-14** | Creación automática de contactos | Como usuario, quiero que un contacto se cree automáticamente cuando una persona inicia una conversación por WhatsApp. | **Given** que una persona no está registrada como contacto y envía un mensaje por WhatsApp, **When** el sistema recibe el mensaje, **Then** el sistema crea un contacto utilizando la información disponible. **Given** que la persona ya está registrada como contacto, **When** el sistema recibe un nuevo mensaje, **Then** el sistema conserva el contacto existente. | **EPIC-05** |
| **HU-15** | Visualización de conversaciones | Como vendedor, quiero visualizar las conversaciones vinculadas a mis contactos para gestionar la comunicación con ellos desde NovaLeads. | **Given** que existe una conversación asociada a un contacto y el vendedor tiene permisos de acceso, **When** solicita la conversación, **Then** el sistema proporciona el historial de mensajes correspondiente. | **EPIC-05** |
| **HU-16** | Notificación de nuevos mensajes | Como usuario, quiero recibir una notificación cuando llegue un nuevo mensaje para poder responder oportunamente. | **Given** que existe una conversación activa y el usuario tiene permisos para recibir sus mensajes, **When** un contacto envía un nuevo mensaje, **Then** el sistema genera una notificación asociada al nuevo mensaje. | **EPIC-05** |
| **HU-17** | Temporizador de conversaciones | Como vendedor, quiero visualizar cuánto tiempo lleva sin responder una conversación para priorizar la atención de los contactos. | **Given** que una conversación tiene un mensaje pendiente de respuesta, **When** transcurre tiempo desde la recepción del mensaje sin una respuesta del vendedor, **Then** el sistema calcula y proporciona el tiempo transcurrido desde la recepción. | **EPIC-05** |
| **HU-18** | Prioridad automática de conversaciones | Como usuario, quiero que las conversaciones sin respuesta reciban una etiqueta de prioridad después de un tiempo determinado para identificar aquellas que requieren atención. | **Given** que una conversación tiene un mensaje sin responder y existe un umbral de tiempo configurado, **When** el tiempo transcurrido supera el umbral, **Then** el sistema asigna automáticamente la prioridad correspondiente a la conversación. | **EPIC-05** |
| **HU-19** | Ordenamiento y filtrado de conversaciones | Como usuario, quiero ordenar y filtrar las conversaciones para encontrar rápidamente aquellas que requieren atención. | **Given** que existen múltiples conversaciones, **When** el usuario solicita las conversaciones utilizando criterios como prioridad, etiquetas o vendedor, **Then** el sistema proporciona únicamente las conversaciones que cumplen los criterios seleccionados. **Given** que el usuario es dueño y selecciona un vendedor como criterio, **When** solicita las conversaciones, **Then** el sistema proporciona las conversaciones asignadas a dicho vendedor. | **EPIC-05** |
| **EPIC-06** | Perfil de usuario | Permitir a los vendedores consultar y actualizar la información de su perfil dentro de NovaLeads. | **Given** que el vendedor ha iniciado sesión, **When** solicita consultar o modificar su información autorizada, **Then** el sistema proporciona o actualiza la información correspondiente. | — |
| **HU-20** | Perfil del vendedor | Como vendedor, quiero consultar y editar mi perfil para mantener actualizada mi información personal dentro de NovaLeads. | **Given** que el vendedor ha iniciado sesión y proporciona información válida, **When** modifica información autorizada de su perfil, **Then** el sistema actualiza y conserva los datos modificados. | **EPIC-06** |
| **EPIC-07** | Landing Page | Proporcionar a los visitantes información sobre NovaLeads, sus principales funcionalidades y beneficios, incluyendo flujos de Call to Action diferenciados para los segmentos objetivo. | **Given** que un visitante accede al sitio web, **When** solicita información sobre NovaLeads, **Then** el sistema proporciona la información correspondiente y permite iniciar el flujo de acceso o registro según el segmento. | — |
| **US-21** | Visualización de información del negocio | Como visitante, quiero visualizar información sobre NovaLeads y sus principales funcionalidades, para comprender qué ofrece la plataforma y cómo puede ayudar a gestionar las relaciones con los clientes. | **Given** que el visitante accede a NovaLeads, **When** solicita información sobre el negocio, **Then** el sistema proporciona información sobre NovaLeads, sus funcionalidades principales y su propuesta de valor. | **EPIC-07** |
| **US-22** | Información para dueños de pymes y startups | Como visitante del segmento de dueños de pymes y startups, quiero visualizar información sobre cómo NovaLeads puede ayudar a gestionar leads, clientes, conversaciones y resultados de ventas, para determinar si la plataforma es adecuada para mi negocio. | **Given** que el visitante pertenece al segmento de dueños de pymes y startups, **When** solicita información dirigida a su segmento, **Then** el sistema proporciona información relacionada con la gestión de leads, clientes, conversaciones y resultados comerciales. | **EPIC-07** |

### Technical Stories

| ID | Título | Descripción | Criterios de Aceptación (Gherkin) |
| :--- | :--- | :--- | :--- |
| **TS-01** | Documentación OpenAPI | Como equipo Developer, quiero implementar documentación automática con Swagger/OpenAPI, para mantener una especificación actualizada y accesible de todos los endpoints de la API. | **Given** que la API se encuentra en ejecución, **When** un cliente solicita la documentación de la API, **Then** el sistema proporciona la especificación actualizada de los recursos, métodos y esquemas disponibles. |
| **TS-02** | Autenticación de usuarios | Como Developer, quiero implementar un endpoint RESTful para autenticar usuarios, para permitir el acceso seguro a los recursos de NovaLeads. | **Given** que el endpoint de autenticación está disponible y las credenciales son válidas, **When** el cliente envía una solicitud `POST` de autenticación, **Then** la API responde con `200 OK` y un token de autenticación. **Given** que las credenciales son inválidas, **When** el cliente envía una solicitud de autenticación, **Then** la API responde con `401 Unauthorized`. |
| **TS-03** | API de gestión de Leads | Como Developer, quiero implementar endpoints RESTful para registrar y consultar leads, para permitir que los clientes gestionen la información de sus leads mediante la API. | **Given** que el cliente está autenticado y proporciona información válida, **When** envía una solicitud `POST` al recurso `/api/v1/leads`, **Then** la API responde con `201 Created` y los datos del lead creado. **Given** que existen leads registrados, **When** el cliente envía una solicitud `GET` al recurso `/api/v1/leads`, **Then** la API responde con `200 OK` y una lista de leads. **Given** que los datos enviados son inválidos, **When** el cliente envía una solicitud `POST`, **Then** la API responde con `400 Bad Request`. |
| **TS-04** | API de gestión de Contactos | Como Developer, quiero implementar endpoints RESTful para consultar y actualizar contactos, para mantener disponible y actualizada la información de los clientes y leads. | **Given** que existe un contacto identificado por su ID, **When** el cliente envía una solicitud `GET` al recurso `/api/v1/contacts/{id}`, **Then** la API responde con `200 OK` y la información del contacto. **Given** que el contacto existe, el cliente tiene permisos de edición y proporciona información válida, **When** envía una solicitud `PUT`, **Then** la API responde con `200 OK` y los datos actualizados. **Given** que el contacto no existe, **When** el cliente realiza una solicitud `GET`, **Then** la API responde con `404 Not Found`. |
| **TS-05** | API de conversaciones | Como Developer, quiero implementar endpoints RESTful para consultar y gestionar conversaciones, para permitir el acceso al historial de comunicación asociado a los contactos. | **Given** que existe una conversación asociada a un contacto y el cliente tiene permisos de acceso, **When** envía una solicitud `GET` al recurso correspondiente, **Then** la API responde con `200 OK` y el historial de mensajes. **Given** que el cliente no tiene autorización para acceder a la conversación, **When** realiza la solicitud, **Then** la API responde con `403 Forbidden`. **Given** que la conversación solicitada no existe, **When** realiza una solicitud `GET`, **Then** la API responde con `404 Not Found`. |
| **TS-06** | API de Dashboard y métricas | Como Developer, quiero implementar endpoints RESTful para obtener métricas de ventas y leads, para proporcionar al frontend los datos necesarios para construir el dashboard. | **Given** que el usuario está autenticado y tiene permisos para consultar métricas, **When** envía una solicitud `GET` al recurso de métricas, **Then** la API responde con `200 OK` y los indicadores correspondientes. **Given** que el usuario no tiene permisos para consultar las métricas, **When** realiza la solicitud, **Then** la API responde con `403 Forbidden`. **Given** que no existen datos para el período solicitado, **When** realiza una solicitud `GET`, **Then** la API responde con `200 OK` y valores vacíos o iguales a cero según corresponda. |
| **TS-07** | Manejo de errores y respuestas HTTP | Como Developer, quiero implementar un mecanismo estandarizado para manejar errores y códigos de respuesta HTTP, para proporcionar respuestas consistentes y comprensibles en todos los endpoints de NovaLeads. | **Given** que el recurso solicitado existe y la operación es válida, **When** el cliente realiza una solicitud correctamente, **Then** la API responde con el código HTTP correspondiente y los datos solicitados. **Given** que la solicitud contiene información inválida, **When** la API procesa la solicitud, **Then** responde con `400 Bad Request` y un mensaje descriptivo. **Given** que el recurso solicitado no existe, **When** la API procesa la solicitud, **Then** responde con `404 Not Found`. **Given** que ocurre un error inesperado en el servidor, **When** la API procesa la solicitud, **Then** responde con `500 Internal Server Error` sin exponer información técnica sensible. |
